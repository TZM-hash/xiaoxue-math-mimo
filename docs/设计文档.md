# 喵喵学习设计文档

## 1. 设计目标

喵喵学习采用离线优先、多学科、可扩展题库的设计。核心目标是：

- 小学生可以快速开始练习，不依赖账号和网络。
- 家长可以看到薄弱点、错因和阶段表现。
- 题目生成过程可控、可测试、可审计。
- Web 与 Android 共用同一套前端资源，减少双端维护成本。
- 后续扩题时尽量只改题库和 seed，不破坏主流程。

## 2. 总体架构

```text
index.html
  ├─ css/*
  ├─ js/storage.js
  ├─ js/runtime-config.js
  ├─ js/cloud-sync.js
  ├─ js/question-bank.js
  ├─ js/chinese-question-bank.js
  ├─ js/english-question-bank.js
  ├─ js/science-question-bank.js
  ├─ js/subject-registry.js
  ├─ js/question-spec-utils.js
  ├─ js/external-question-seeds.js
  ├─ js/*-question-generator.js
  ├─ js/question-generator.js
  ├─ js/practice-engine.js
  ├─ js/question-rules-engine.js
  ├─ js/report.js / js/pet.js / js/import-export.js
  └─ js/app.js
```

模块通过 `window.MathCamp*` 命名空间暴露能力，没有使用前端框架和打包器。这样做的好处是部署简单、Android WebView 可直接加载；代价是脚本顺序非常重要。

## 3. 运行时分层

表现层：

- `index.html` 定义页面结构、弹窗、练习卡片、报告页、宠物空间。
- `css/` 定义主题、动画、特效和响应式布局。

应用层：

- `js/app.js` 管理全局状态、DOM 绑定、答题流程、报告入口、宠物奖励和系统设置。
- `js/home-route.js` 负责首页今日学习路线。
- `js/report.js` 负责学习报告渲染。
- `js/pet.js` 和 `js/pet-economy.js` 负责宠物成长与奖励经济。

题目层：

- `js/question-bank.js` 是数学主题库。
- `js/chinese-question-bank.js`、`js/english-question-bank.js`、`js/science-question-bank.js` 是语文、英语、科学题库。
- `js/question-generator.js` 是统一入口，根据 `pointId` 或 `subject` 分发到对应学科生成器。
- `js/external-question-seeds.js` 提供扩展题源。

质量层：

- `js/question-rules-engine.js` 定义题目质量规则。
- `tests/` 中的测试脚本验证题库、生成器、布局、Android 镜像和浏览器行为。

平台层：

- Web/PWA 直接加载根目录资源。
- Android WebView 加载 `android/app/src/main/assets/www/` 镜像资源。
- `AndroidBridge` 提供少量 JS 到 Android 的桥接能力。

## 4. 题目生成流程

统一入口：

```text
MathCampQuestionGenerator.makeQuestion(deps, point, options)
```

流程：

1. 如果存在扩展题源，且 `options.preferExternal` 为 true，优先生成扩展题。
2. 非严格模式下，按较低概率混入扩展题源，提升题目丰富度。
3. 严格模式默认不使用扩展题源，避免专项规则测试受随机题影响。
4. 根据 `point.subject` 或 `point.id` 前缀分发：
   - `c`：语文
   - `e`：英语
   - `s`：科学
   - 其他：数学
5. 生成后经过 `ensureQuestionMatchesRule` 做规则兜底。

选择题使用 `js/question-spec-utils.js` 的 `choiceLayout` 生成选项，保证：

- 正确答案位置会洗牌。
- `answer` 与当前选项字母一致。
- `answerLabel` 与当前正确选项一致。
- `acceptedAnswers` 包含字母、文本和标签形式。

## 5. 多学科设计

每个学科都有独立题库和生成器：

```text
MathCampQuestionBank
MathCampChineseQuestionBank
MathCampEnglishQuestionBank
MathCampScienceQuestionBank
```

非数学题必须带 `subject` 字段，避免被数学规则当成数字题处理。数学题默认不带 `subject`，保持旧规则兼容。

学科隔离测试由 `tests/subject-isolation.test.js` 负责，防止语文、英语、科学题混入数学流程或错用数学判分规则。

## 6. 扩展题源设计

扩展题源模块：

```text
js/external-question-seeds.js
```

公开接口：

```text
window.MathCampExternalQuestionSeeds = {
  sources,
  forPoint,
  makeQuestion
}
```

核心数据结构：

```text
SOURCE：来源元数据
BANK：pointId -> seed[]
```

每个 seed 应包含：

- `id`
- `answerType`
- `text` 或 `prompt`
- `answer` 或 `correct`
- `acceptedAnswers` 或 `wrongs`
- `explanation`
- `steps`
- `questionType` 或 `templateType`
- `sourceMeta`

来源类型：

- `openResource`：公开资源或官方教材/课标参考。
- `inspiredOriginal`：参考题型结构后的原创改写。

测试要求：

- 每科至少覆盖指定 8 个重点知识点。
- 总 seed 数不少于 32。
- 每科都包含官方/区域来源。
- 每科都包含国内题库网站题型参考。
- 选择题洗牌后答案不能固定为 A。

## 7. 学习数据设计

数据以本地存储为主，通过 `js/storage.js` 统一读写。`js/app.js` 中的 `STORE` 定义主要存储 key。

保存内容包括：

- 当前学生档案。
- 年级、学科、题型设置。
- 练习记录。
- 错题与错因。
- 自适应掌握度。
- 宠物状态、奖励、任务进度。
- 系统设置、主题、特效。

设计原则：

- 本地数据可独立运行。
- 云同步不是启动依赖。
- 导入导出用于备份和迁移。
- 数据结构变更应保持兼容旧记录。

## 8. Android 设计

Android 端是轻量 WebView 外壳：

```text
MainActivity
  └─ WebView
      └─ file:///android_asset/www/index.html
```

WebView 配置：

- 启用 JavaScript。
- 启用 DOM Storage。
- 允许 file access。
- 禁用缩放。
- 文本缩放固定为 100。
- 支持媒体播放不强制用户手势。

桥接对象：

```text
AndroidBridge
  ├─ showToast(message)
  └─ getUserAgent()
```

Android 端不维护独立业务逻辑，所有题库和页面都来自 Web 资源镜像。

## 9. 测试设计

主要测试命令：

```powershell
$ErrorActionPreference = 'Stop'
npm test
```

测试分组：

- `test:questions`：题库结构、外部题源、答案模式、多学科隔离、手写输入、覆盖统计。
- `test:rules`：题目规则、边界、奖励、报告、课程元数据、多学科集成。
- `test:layout`：页面结构、脚本加载顺序、UTF-8、Android 镜像一致性。
- `test:browser`：浏览器冒烟测试。

Android 镜像检查：

```powershell
$ErrorActionPreference = 'Stop'
npm run sync:android:check
```

## 10. 关键设计约束

- 修改 `index.html` 脚本顺序要同步更新布局测试。
- 修改 Web 资源后要同步 Android assets。
- 新题目必须有解析和步骤。
- 非数学题必须标记 `subject`。
- 数学专题题干要满足规则关键词，例如百分数题要包含 `%`、`百分` 或 `折`。
- 小数显示要保留两位，避免规则测试失败。
- 选择题不要手写固定 `A/B/C/D` 答案，应使用 `choiceLayout`。
- 扩展题源要记录 `sourceMeta`，便于审计和后续扩展。
