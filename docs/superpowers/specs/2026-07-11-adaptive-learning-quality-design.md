# 自适应学习质量优化设计

## 目标

在保持四学科现有题库结构和每学科四条错因快捷选项不变的前提下，提高题目难度可信度、错题复习效果、抽题多样性、提示质量和掌握度判断准确性。

## 约束

- 手机端每个学科继续只显示四条错因，不增加细分错因选择。
- 细分能力诊断由后台自动推断，只用于掌握度、抽题和学习报告。
- 不修改现有题目对象的必填结构；新增学习记录字段均为可选字段。
- 旧档案缺少新字段时应正常加载，并在后续答题中渐进补齐。
- Web 资源修改后必须同步到 `android/app/src/main/assets/www/`。
- 不涉及发布配置、安全策略、远程服务或数据库改造。

## 总体架构

新增独立的学习质量模块 `js/learning-quality-engine.js`，负责纯计算逻辑，不直接操作 DOM 或持久化。`js/app.js` 继续负责页面状态、事件、档案写入和练习流程，通过该模块计算诊断、掌握度、难度、复习阶段和抽题权重。

题目生成器继续生成原有题目对象。学习质量模块只读取已有的 `subject`、`pointId`、`topic`、`answerType`、`questionType`、`templateType`、`sourceType`、`commonPitfalls` 和题目文本等信息，不要求生成器迁移到新结构。

## 学习证据记录

每次答题记录增加以下可选字段：

- `confidence`: `sure`、`unsure`、`guess` 或空字符串。
- `elapsedMs`: 当前题从展示到首次提交的用时。
- `hintLevel`: 本题使用过的最高提示等级，范围 0 至 3。
- `firstTryCorrect`: 首次提交是否正确。
- `diagnostic`: 后台细分诊断标签。
- `difficultyScore`: 答题时题目的动态难度分，范围 1 至 5。
- `masteryDelta`: 本次答题对掌握度产生的变化值。

这些字段写入历史记录和当前轮次记录。错题记录保存最近诊断、提示等级和信心，但前台仍只展示所属学科的四条错因。

## 后台细分诊断

内部诊断统一使用稳定英文标识：

- `reading`: 审题或信息定位问题。
- `concept`: 概念、公式、单位或规则不清。
- `method`: 解题方法或步骤选择不当。
- `calculation`: 运算、符号、进退位或数值错误。
- `expression`: 语文表达、格式或答案完整性问题。
- `spelling`: 英语单词、字母或拼写问题。
- `evidence`: 科学观察、变量、证据或结论问题。
- `uncertain`: 证据不足，暂不细分。

诊断依据包括学科、知识点、题型、答案类型、用户答案、四条错因、提示使用、耗时和题目常见易错点。诊断不会替代四条错因，而是在其下增加内部维度。

## 掌握度模型

现有 `attempts`、`correct`、`level`、`streak` 字段继续保留，并增加：

- `score`: 0 至 100 的连续掌握分。
- `diagnostics`: 各内部诊断标签的累计证据。
- `lastPracticedAt`: 最近练习时间。
- `stableCorrect`: 无高级提示且非猜测状态下的稳定正确次数。

基础变化规则：

- 确定、无提示、正常耗时答对：明显增加掌握分。
- 不确定答对：中等增加掌握分。
- 猜测答对或使用三级提示答对：少量增加，不计稳定正确。
- 使用一级或二级提示答对：按提示等级降低增量。
- 答错：降低掌握分，并增加对应诊断证据。
- 连续稳定答对才提升原有 `level`；单次猜对不触发升级。

旧档案没有 `score` 时，根据原有正确率、等级和连续正确次数初始化，不重置用户进度。

## 动态难度校准

题目难度由静态先验和真实表现共同组成：

- 静态先验：年级、题型、答案类型、步骤数量、文本长度和题目已有难度信息。
- 动态证据：同知识点近期正确率、平均用时、提示使用率、猜测率和首次正确率。

难度输出为 1 至 5。样本不足时以静态先验为主；样本达到最低数量后逐步增加真实表现权重，避免少量答题导致难度剧烈波动。

## 答题信心交互

输入区附近增加紧凑三段选择：`确定`、`不确定`、`猜的`。

- 信心选择可选，不阻止提交。
- 每题开始时默认不选中。
- 选择后保持到本题提交，不跨题继承。
- 移动端使用单行三段控件，不增加弹窗。
- 选择题、判断题和输入题均支持信心记录。
- 未选择时按中性证据处理，不惩罚用户。

## 三级提示

现有提示入口改为逐级展开：

1. 一级提示：提醒审题方向或应该观察什么。
2. 二级提示：指出知识点、方法、公式或证据类型。
3. 三级提示：给出关键步骤或中间关系，但不直接显示最终答案。

每次点击提升一级，并记录最高等级。切换题目后重置。完整答案仍由现有“查看答案”入口负责。

## 题目质量评分

质量评分为 0 至 100，至少检查：

- 题干是否明确且有作答动作。
- 答案是否唯一、可判分且未在题干泄漏。
- 选择题是否有足够且不重复的干扰项。
- 干扰项是否属于相近误区，而不是无关或荒谬内容。
- 解析是否解释原因，并包含足够步骤。
- 题目、答案、解析是否与知识点一致。
- 是否含制作说明、来源说明或通用占位话术。

低于硬阈值的题不进入普通、自适应、每日和闯关抽题；错题复习仍可读取历史题目，但会优先生成合格变式。质量问题通过现有审计接口输出，不在学生页面展示。

## 语义重复控制

为题目生成内部 `familyKey`，由知识点、题型、模板类型和归一化题干结构组成。归一化时移除数字、姓名、单位数值和选项顺序差异。

同一轮优先覆盖不同 `familyKey`。近期历史中相同题干继续完全避开；相同 `familyKey` 则降低权重，而不是永久禁止，以免小题库无法组卷。

## 错题变式题链

错题复习按以下阶段推进：

1. `scaffold`: 更简单的铺垫题，聚焦缺失概念或单一步骤。
2. `sameModel`: 同知识点、同方法但更换数据或情境。
3. `transfer`: 同知识点迁移到不同题型或真实情境。
4. `delayed`: 按间隔复习重新检验稳定掌握。

答对后推进阶段，答错后退回 `scaffold`。连续稳定答对且完成迁移题后，才移入已掌握错题。现有 `reviewStage` 和 `dueDate` 继续使用，并增加可选 `chainStage`。

## 抽题策略

自动组卷依次保证：

- 到期错题和未完成题链优先。
- 掌握分低或诊断证据强的知识点获得更高权重。
- 难度目标接近用户当前掌握水平，避免整组过难或过易。
- 题型、答题形式、来源和 `familyKey` 尽量均衡。
- 近期题目和近期知识点继续降权。
- 质量不合格题直接排除。

专项练习仍严格限制在用户选择的知识点内，但内部题型和题目家族保持均衡。

## 综合练习策略

复用现有入口，不增加复杂导航：

- 普通练习：当前知识点或年级混合。
- 每日练习：到期复习、薄弱点和新题混合。
- 错题复练：按题链阶段出题。
- 限时小测：优先使用已见知识点，降低新题比例。
- 周复习：从本周练习中抽取薄弱诊断、到期题和迁移题。

## 数据兼容与异常处理

- 所有新增字段读取时提供默认值。
- 非法信心、提示等级、难度和掌握分在档案归一化时修正。
- 质量门禁导致候选不足时，允许回退到通过硬规则但质量分较低的题，确保可以完成组卷。
- 无法推断内部诊断时使用 `uncertain`，不伪造具体错误原因。
- 不增加网络依赖，全部计算和记录保持本地运行。

## 测试与验收

- 单元测试覆盖信心、提示、诊断、掌握分、难度、质量评分、题目家族和题链推进。
- 规则测试确认四学科错因始终各自保持四条。
- 兼容性测试使用旧档案验证无数据丢失。
- 抽题测试确认低质量题被隔离、题型与题目家族更加均衡。
- 浏览器测试覆盖三段信心控件、三级提示和移动端布局。
- 桌面与 390×844 移动端四学科截图不得出现横向溢出或主要操作遮挡。
- `npm test`、Android 资源同步检查和 `git diff --check` 必须通过。
