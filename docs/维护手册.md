# 喵喵学习维护手册

## 1. 日常维护原则

维护时优先遵守三条原则：

- 小改动先做定向验证，大改动跑完整测试。
- Web 资源变更后必须同步 Android assets。
- 题库扩展必须同时补充或更新测试。

推荐每次改动前查看状态：

```powershell
$ErrorActionPreference = 'Stop'
git status --short --branch
```

## 3. 修改 Web 页面

涉及文件：

- `index.html`
- `css/*`
- `js/app.js`
- 相关功能模块

维护步骤：

1. 修改 Web 端文件。
2. 如果新增脚本，确认 `index.html` 加载顺序。
3. 更新 `tests/frontend-layout.test.js` 中的脚本加载或 DOM 契约。
4. 执行 `npm run test:layout`。
5. 执行 `.\scripts\sync-android-assets.ps1`。
6. 执行 `npm run sync:android:check`。
7. 视改动范围执行 `npm test`。

注意：

- 当前没有构建器，脚本顺序就是依赖顺序。
- 不要只修改 Android 镜像文件，应先修改根目录 Web 资源，再同步。
- Android 镜像中的手工改动会被同步脚本覆盖。

## 4. 扩展数学题库

常见文件：

- `js/question-bank.js`
- `js/question-generator.js`
- `js/question-rules-engine.js`
- `tests/question-rules.test.js`

维护要求：

- 新知识点必须有稳定 `id`。
- 年级、topic、label、helper 要完整。
- 题目答案必须可判分。
- 如果是专题题，题干要包含规则引擎需要的语境关键词。
- 需要补充规则测试或覆盖测试。

数学规则示例：

- `g2-table-div` 应包含 `÷`、`平均分`、`每人`、`分成` 等除法语境。
- `percent` topic 应包含 `%`、`百分` 或 `折`。
- `fraction` topic 应包含 `/`、`分数`、`百分` 或 `几分之`。
- 小数展示应使用两位格式，例如 `5.90`。

## 5. 扩展语文、英语、科学题库

常见文件：

- `js/chinese-curriculum-data.js`
- `js/chinese-question-bank.js`
- `js/chinese-question-generator.js`
- `js/english-curriculum-data.js`
- `js/english-question-bank.js`
- `js/english-question-generator.js`
- `js/science-curriculum-data.js`
- `js/science-question-bank.js`
- `js/science-question-generator.js`

维护要求：

- 非数学知识点和题目必须带 `subject`。
- 题目要有 `explanation` 和 `steps`。
- 答案类型优先使用 `choice` 或 `text`，保证客观判分。
- 英语音频提示依赖浏览器或 WebView 的 `speechSynthesis`。
- 阅读题题干应结构化，避免长文本挤成一行。

验证命令：

```powershell
$ErrorActionPreference = 'Stop'
node tests/chinese-question-bank.test.js
node tests/english-question-bank.test.js
node tests/science-question-bank.test.js
node tests/subject-isolation.test.js
npm run test:rules
```

## 6. 扩展外部题源 seed

主要文件：

```text
js/external-question-seeds.js
tests/external-question-seeds.test.js
```

维护步骤：

1. 先在测试里增加期望覆盖的 `pointId` 或来源约束。
2. 运行测试确认失败。
3. 在 `SOURCE` 中补充来源元数据。
4. 在 `BANK` 中按 `pointId` 增加 seed。
5. 运行外部题源测试。
6. 运行题目规则测试。
7. 同步 Android assets。
8. 运行完整测试。

推荐命令：

```powershell
$ErrorActionPreference = 'Stop'
node tests/external-question-seeds.test.js
node tests/question-rules.test.js
.\scripts\sync-android-assets.ps1
npm run sync:android:check
npm test
```

seed 内容要求：

- `id` 全局稳定。
- `sourceMeta` 必须有 `kind`、`name`、`url`、`license`。
- 选择题使用 `correct` 和 `wrongs`，不要预设正确字母。
- 文本题的 `answer` 建议用字符串或可转数字的值。
- `acceptedAnswers` 覆盖常见输入形式。
- `explanation` 说明为什么。
- `steps` 至少两步。

## 7. 维护 Android 包

修改 Web 资源后：

```powershell
$ErrorActionPreference = 'Stop'
.\scripts\sync-android-assets.ps1
npm run sync:android:check
```

构建 debug：

```powershell
$ErrorActionPreference = 'Stop'
Set-Location .\android
.\gradlew.bat assembleDebug
```

构建 release：

```powershell
$ErrorActionPreference = 'Stop'
$env:KEYSTORE_PASSWORD = '<替换为实际 keystore 密码>'
$env:KEY_PASSWORD = '<替换为实际 key 密码>'
Set-Location .\android
.\gradlew.bat assembleRelease
```

维护注意：

- `MainActivity` 只负责 WebView 容器，不应加入复杂业务逻辑。
- `AndroidBridge` 只放必要桥接方法。
- 修改 `applicationId`、`versionCode`、`versionName` 后要同步发布记录。
- 如果 Android 页面表现异常，先确认 assets 是否同步。

## 8. 常见问题排查

问题：Android assets 检查失败。

处理：

```powershell
$ErrorActionPreference = 'Stop'
.\scripts\sync-android-assets.ps1
npm run sync:android:check
```

问题：选择题正确答案总是 A。

排查：

- 检查是否绕过了 `choiceLayout`。
- 检查 seed 是否手写了固定 `answer: "A"`。
- 运行 `node tests/external-question-seeds.test.js`。

问题：新增数学题规则测试失败。

排查：

- 查看失败知识点 topic。
- 检查题干、解析、答案标签是否包含规则所需语境。
- 检查小数是否保留两位。
- 检查答案是否能被 `Number(question.answer)` 解析。

问题：非数学题被当成数学题。

排查：

- 知识点是否有 `subject`。
- 题目是否保留 `subject`。
- `pointId` 是否以 `c`、`e`、`s` 对应学科前缀开头。

问题：浏览器冒烟测试失败。

排查：

- 是否安装 Microsoft Edge。
- 页面是否有脚本报错。
- 最近是否改了 DOM id 或关键入口按钮。
- 运行 `npm run test:layout` 查看结构契约。

问题：本地数据保存失败。

排查：

- 浏览器是否禁用本地存储。
- WebView 是否启用 DOM Storage。
- 是否在隐私模式或受限环境中运行。
- 可提示用户导出备份后清理旧数据。

## 9. Git 维护流程

推荐流程：

```powershell
$ErrorActionPreference = 'Stop'
git status --short --branch
npm test
git add -- <相关文件>
git commit -m "<清晰的提交信息>"
git push origin master
```

推送 GitHub 如果遇到代理问题，可先检查：

```powershell
$ErrorActionPreference = 'Stop'
git config --show-origin --get-regexp '^(http|https)\..*proxy$|^http\.proxy$|^https\.proxy$'
```

如果 GitHub 代理可用但 TLS 失败，可临时使用：

```powershell
$ErrorActionPreference = 'Stop'
git -c http.version=HTTP/1.1 push origin master
```

## 10. 发布维护清单

发布前：

- 更新版本号。
- 同步 Android assets。
- 运行 `npm run sync:android:check`。
- 运行 `npm test`。
- 构建 APK。
- 安装 APK 做手动冒烟。
- 记录 commit、APK 文件名、发布时间和主要变更。

发布后：

- 保留上一版 APK。
- 标记 Git commit。
- 如发现题库问题，优先新增测试复现，再修复。
